# フォトチェンジ（photo-converter）統合設計書

**アプリ名**: フォトチェンジ
**タグライン案**: 写真をドット絵・手描き風イラストに変換
**URL**: https://photo-converter.yamashin-app.com
**確定済み方針**（2026-08-08）:
1. drawing本番コードのサルベージ完了（`salvage/backend/`、差分はapp.pyの2行のみ）
2. 検索公開する（noindex解除は新アプリ公開時）
3. ドメイン: photo-converter.yamashin-app.com（旧2ドメインは新アプリ公開後に301リダイレクトで閉鎖）
4. 技術: Next.js (App Router) + TypeScript + 静的エクスポート。変換エンジンは純TSモジュール（Web Worker実行）。CSS Modules（Tailwind不使用）。PWA対応。HEICはlibheif-js(WASM)動的読み込み
5. アナリティクス: GA4導入（プライバシーポリシー記載 + Cookie同意バナー必須）
6. 多言語対応は初期スコープ外（日本語のみ、構造だけ用意）

## 1. コンセプト

「写真を1枚選ぶだけで、ドット絵にも手描き風イラストにも変換できる」統合ツール。
変換は**全てブラウザ内で完結**（画像はサーバーに送信されない = プライバシーが実装レベルで保証）。

旧2ツールの統合:
- convert-photo-16bit（PHP/GD）→ ドット絵系スタイル
- convert-photo-drawing（Flask/OpenCV）→ 手描き風スタイル
- 16bitの「手描き風(smooth)」モードはdrawingのパイプライン（前処理が豊富）に吸収統合

## 2. 機能マップ

### 2.1 変換スタイル（3種）

| スタイル | 由来 | パイプライン |
|---|---|---|
| ドット絵（レトロ） | 16bit `retro` | NEAREST縮小 → パレット変換 → ディザ → 元サイズ拡大 |
| ドット絵（整数倍） | 16bit `integer` | 同上、拡大が整数倍でエッジ完全シャープ |
| 手描き風イラスト | drawing + 16bit `smooth` 統合 | ぼかし/bilateral/median → CLAHE(オプション) → 影除去(ガンマ0.4) → NEAREST縮小 → K-means量子化 → テクスチャ除去 → DoGアウトライン(オプション) → 拡大 |

### 2.2 パラメータ

| パラメータ | 値 | 由来・備考 |
|---|---|---|
| ピクセルサイズ | 2 / 4 / 8 / 12 / 16 | 両ツール統合。全スタイル共通化 |
| 色数 | 4 / 8 / 16 / 32 / 64 | drawing由来。ドット絵はデフォルト16（「16bit風」ブランド維持） |
| パレット | 自動 + 固定8種 | 16bit由来。gameboyの重複色4組を修正（実効16色化） |
| パレット抽出方式 | MedianCut / Popularity / Luminance / K-means | 16bitの3種 + drawingのK-means = 4種 |
| ディザリング | なし / Floyd-Steinberg / Riemersma / Ordered 2×2, 4×4, 8×8 / Patterning 2×2, 4×4, 8×8 | 16bitの9種を採用。距離計算をユークリッドに統一、乱数はシード付き（決定的出力） |
| アウトライン | なし / ソフト(DoG) / 自動(Sobel系) + 強度 | 両ツールの実装を統合 |
| 彩度 | スライダー 0〜200% | drawing由来（16bitのvibrancyは吸収） |
| コントラスト強化 | ON/OFF（CLAHE） | drawing由来 |
| 影除去 | ON/OFF + 強度（手描き風のみ） | drawing由来 |

### 2.3 入出力

- **入力**: JPEG / PNG / GIF / WebP / HEIC・HEIF（WASM）。D&D / ファイル選択 / **クリップボード貼り付け** / **PWA共有ターゲット**（スマホの共有メニューから直接起動）
- **解像度制限の実質撤廃**: 旧800〜1200px制限を廃止（クライアント処理のため。端末保護の上限のみ設定、例: 長辺8192px）
- **出力**: PNG / WebP、サイズ選択（処理解像度 / 元サイズ / 2倍）
- EXIF orientation対応（旧版は未対応 = 横向き写真バグの解消）

### 2.4 UX刷新（旧版の弱点解消）

| 旧版の問題 | 新版 |
|---|---|
| 設定変更のたびに画像を再アップロード | **即時プレビュー**（Worker + デバウンスでリアルタイム再変換） |
| 偽物のプログレスバー | Workerからの**実進捗** + キャンセル（AbortController相当） |
| 比較スライダーはdrawingのみ | 全スタイルで比較スライダー + **ズーム/パン** + ピクセルグリッド表示 |
| 設定が毎回リセット | **プリセット保存**（localStorage）+ **設定込み共有URL**（クエリパラメータ） |
| ダークモードなし、CSS変数なし | デザイントークン（CSS変数）で構築、ダークモード対応 |
| a11y欠陥（存在しないID参照、ARIAゼロ） | ラベル/ARIA/ライブリージョン/キーボード操作を初期から設計 |
| レスポンシブは微調整のみ | モバイルファースト（利用の主戦場はスマホ写真の変換） |

### 2.5 PWA

- manifest.json（アイコン192/512 + maskable、theme-color、apple-touch-icon）
- Service Worker: アプリシェルのプリキャッシュ = **完全オフライン動作**（変換はクライアント処理なので通信不要）
- `share_target`: スマホの写真共有メニューに「photo-converter」を出す
- 旧版の `?v=time()` キャッシュバスターは廃止（ビルドハッシュで管理）

### 2.6 公開・SEO

- index許可 / canonical / OGP（画像実体も用意）/ Twitter Card / JSON-LD（WebApplication、実機能と一致させる）/ sitemap / robots.txt
- 旧2ドメイン（convert-to-16bitstyle / convert-to-drawing）から301リダイレクト
- プライバシーポリシー刷新: 「画像はそもそも送信されません」を訴求軸に
- アナリティクス: GA4導入（Cookie同意バナー + プライバシーポリシー記載）

### 2.7 初期スコープ外（将来拡張、エンジン分離設計で担保）

- 新エフェクト（油絵風、アニメ調、CRT風など）
- GIFアニメ対応、バッチ変換、変換履歴
- 共有URL発行・OGP動的生成（サーバー機能 → その時はAPI Routes or Hono）
- 多言語対応（構造だけ用意し、初期は日本語のみ）

## 3. 画面設計（1画面完結）

```
┌──────────────────────────────────────┐
│ ヘッダー: ロゴ / ダークモード切替      │
├──────────────────────────────────────┤
│ [画像未選択時]                        │
│   ドロップゾーン（D&D/クリック/ペースト）│
│   ↓ サンプル画像でお試しボタン         │
├──────────────────────────────────────┤
│ [画像選択後]                          │
│  ┌─────────────┐ ┌─────────────────┐ │
│  │ プレビュー     │ │ コントロール      │ │
│  │ ・比較スライダー│ │ 1. スタイル(3択) │ │
│  │ ・ズーム/パン  │ │ 2. 基本(サイズ/  │ │
│  │ ・実プログレス │ │    色数/パレット) │ │
│  │              │ │ 3. 詳細(折りたたみ│ │
│  │              │ │  ディザ/輪郭/色調)│ │
│  └─────────────┘ └─────────────────┘ │
│  [ダウンロード PNG/WebP] [プリセット] [共有] │
├──────────────────────────────────────┤
│ フッター: 使い方 / 規約 / プライバシー / X │
└──────────────────────────────────────┘
```

- デスクトップ: プレビュー左・コントロール右の2カラム
- モバイル: プレビュー上・コントロール下（スクロール追従でプレビューは上部固定）
- 設計思想: **「スタイルを選ぶ→すぐ結果が見える」を最短動線に**。詳細パラメータは折りたたみで隠し、初見ユーザーには3タップで完結させる

## 4. アーキテクチャ

```
photo-converter/（新リポジトリ）
├── src/
│   ├── engine/              # 純TS変換エンジン（フレームワーク非依存）
│   │   ├── palettes/        # 固定パレット定義・抽出4方式
│   │   ├── dithering/       # 9種（共通インターフェース）
│   │   ├── filters/         # blur/bilateral/CLAHE/DoG/彩度/ガンマ
│   │   ├── styles/          # 3スタイルのパイプライン定義
│   │   └── worker.ts        # Web Workerエントリ（進捗通知付き）
│   ├── app/                 # Next.js App Router（静的エクスポート）
│   ├── components/          # UI（CSS Modules）
│   └── lib/                 # HEIC読込(動的import)、プリセット、URL状態
├── public/                  # manifest / アイコン / OGP画像
└── tests/
    ├── unit/                # パレット16色検証、距離計算等
    └── golden/              # 基準画像との出力一致テスト
```

- 処理順序は旧仕様の設計意図を踏襲: パレット変換 → 彩度 → アウトライン → ディザリング（SPECIFICATION.txt 16.1）
- エンジンは決定的出力（シード付き乱数）= ゴールデンテストで回帰を機械検証
